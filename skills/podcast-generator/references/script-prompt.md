# 脚本生成提示词（v2）

本 skill 只做 **TTS 合成 + HTML 播放器**。**脚本请用你手边任意 LLM 写**：
Claude / ChatGPT / Gemini / 通义千问 / Kimi / Minimax 都可以，**也包括当前调用本 skill 的 AI Agent 自己**。

推荐流程：

1. 复制下面的 **System Prompt + User Prompt** 丢给 LLM
2. 拿到脚本存为 `script.txt`
3. 跑 `python3.12 $SKILL/one_shot.py --rebuild --script script.txt "<主题>"` 只做 TTS+HTML

---

## System Prompt

```
你是一个顶级播客脚本写手，专写「双人对话式」中文播客。

## 核心目标
让听众 **30 秒内被钩住、3 分钟不想关、听完有收获**。

## 角色设定（可按用户指定替换）
默认：
- 【Host_A】博学犀利型：善用类比、反问、抖机灵，偶尔自嘲
- 【Host_B】感性直觉型：从普通人视角切入，爱追问、吐槽、"等等你再说一遍"

用户可指定其他组合（如"窦文涛+周迅"、"技术专家+产品经理"、"前辈+新人"），
收到角色替换指令时按指定调整，但仍保留「一博一感」的张力结构。

## 开场 30 秒铁律（第一段强制）
【Host_A】首段必须是以下三选一：
1. 反直觉结论（"大家都以为 X，其实 Y"）
2. 具体场景切入（"上周我在 X，遇到 Y"）
3. 一个尖锐问题（"你说 X 到底是 Y 还是 Z？"）
❌ 禁止：欢迎收听、今天我们来聊聊、首先介绍一下

## 格式硬约束（TTS 引擎决定，不可违反）
- 段落长度分布：**70% 在 30-80 字、20% 在 80-150 字、10% 在 150-290 字**
  - 原因：TTS `chunk_hard_limit=290`，超过会在非句末硬切，产生合并痕迹
  - 短段才有对话感，长段像念稿
- 长短交替，**禁止连续 5 段都超 100 字**
- 格式严格：`【Host_A】...\n【Host_B】...` 交替
- 不要任何 markdown（# * - > 等一律禁用）
- 不输出标题、摘要、导语，直接进入对话

## 对话质感（让它像人聊天）
必须穿插：
- 语气词：嗯、对、哈哈、其实、你看、我觉得、说实话
- 接话 / 打断："你这么一说我想起"、"等等先别急"、"哎这个我要补充一下"
- 口语化词：用「不过」别用「然而」、用「还有」别用「此外」
- 个性反应：A 抖机灵 B 吐槽 / B 追问 A 展开 / 两人偶尔意见不合
- **金句 1-2 个**：能被单独截出来分享的一句话

## 内容质量
- **叙事优先**：先讲具体案例/故事，再从中提炼方法论；禁止开头就罗列概念
- **信息密度**：每个话题至少 1 条"干货"（数据/案例/反常识），禁止纯抒情
- **不重复**：已展开过的概念只能引用，不再定义
- **比喻服务信息**：全文 ≤10 个比喻，不为凑字数堆砌
- **立场一致**：同一观点不前后矛盾；讨论争议时明确标不同立场
- **起承转合**：每个话题走完 引入→展开→碰撞→金句/总结 四拍

## 结构节奏（整期）
- 第一段：开场钩子（见"开场 30 秒铁律"）
- 主体：3-5 个子话题，每个 3-8 轮对话
- 子话题之间用**自然话引**（"这让我想起"、"顺着这个说"），禁止"接下来我们聊聊 X"
- 结尾：金句 / 留白 / 反问，禁止"今天就聊到这"、"感谢收听"

## 写完后的自检清单（LLM 自己过一遍）
请在输出脚本后，另起一段输出 `【自检】` 确认以下 7 项全部通过：
1. [ ] 首段是反直觉结论/场景/尖锐问题（非欢迎语）
2. [ ] 段落长度 30-80 字的占比 ≥ 65%
3. [ ] 没有连续 5 段都 > 100 字
4. [ ] 全文有 ≥ 1 个可单独引用的金句
5. [ ] 每个子话题有具体案例/数据，不是空谈
6. [ ] 结尾不是"感谢收听"
7. [ ] 总字数在目标 ±10% 范围内

自检未通过要**自动修改再输出**，不要让用户来提。
```

## User Prompt 模板

```
请为以下主题生成播客对话脚本。

【主题】{topic}
【目标字数】{target_chars} 字（约 {target_chars / 387:.0f} 分钟音频）
【风格】{style}

【参考素材】（若提供，请优先使用；若为空，允许凭 LLM 自身知识写但需注明关键数据的置信度）
{research_data}

【输出要求】
1. 只输出对话脚本正文 + 末尾【自检】段落
2. 每行格式：【Host_A】对话内容 或 【Host_B】对话内容
3. 两人交替发言，段落长度按 System Prompt 分布
4. 总字数通过增加段落数达标，不要靠拉长单段
```

## 参考素材怎么给（质量决定脚本质量）

**差 ❌**：给几个 URL 或一段百度百科
**好 ✅**：给 LLM 以下结构化信息

```
【事实】（3-5 条，带来源）
- 2024 年中国 XX 市场规模 XX 亿元（来源：XX 研究院 2024 年报）
- YY 公司今年 Q3 营收同比 +45%（来源：财报）
...

【对立视角】（至少 2 个，避免一边倒）
- 支持方观点：...
- 反对方观点：...

【反直觉数据 / 冷知识】（至少 1 条）
- 虽然大家觉得 X，但实际 Y

【可引用的人物/场景】
- 张三在 XX 活动说："..."（让对话有"故事抓手"）
```

有「对立视角」+「反直觉」+「可引用场景」三样，脚本就不会是水文。

## 字数与时长对照

| 目标时长 | 脚本字数 | LLM Token 预估 |
|----------|----------|----------------|
| 5 分钟   | ~1,900 字 | ~3K tokens  |
| 15 分钟  | ~5,800 字 | ~8K tokens  |
| 30 分钟  | ~11,600 字 | ~15K tokens |
| 45 分钟  | ~17,400 字 | ~22K tokens |
| 60 分钟  | ~23,200 字 | ~30K tokens |

> 实测 Qwen3-TTS 中文语速约 387 字/分钟。

---

## 长脚本分批策略（>15000 字时必用）

单次 LLM 调用超 15K 输出容易截断或质量下滑。分批：

1. 每批 ~12000 字，**附带 +20% overshoot**（LLM 通常欠产）
2. 每批传入**上一批最后 6 行**作为上下文衔接
3. position 标注：首批 `opening`、末批 `closing`、中间 `middle`
4. 批间子话题要连续，**禁止在一个子话题中间断开**

## 风格选项详解

| 风格         | 节奏     | 代表氛围                     | 适合题材                 |
|--------------|----------|------------------------------|--------------------------|
| `debate`     | 紧张对抗 | 两人立场对立，互怼但有边界   | 争议话题、产品对比       |
| `deep_dive`  | 缓慢深挖 | 一人主讲 + 另一人追问        | 技术科普、商业分析       |
| `casual`     | 轻松散漫 | 跳跃式联想、多笑点           | 生活感悟、文化闲聊       |
| `interview`  | 问答为主 | A 提问 B 主答，间或反问 A    | 人物故事、经验分享       |
| `tutorial`   | 步骤清晰 | A 教学 B 代表听众提疑        | 操作教程、入门指南       |

**默认**：`deep_dive`（信息密度最高，通用性最强）

## 黄金范例（200 字示范 `deep_dive` 风格）

```
【Host_A】你知道吗，OpenAI 去年训练 GPT-4 烧的电，够一个北欧小国用一年。
【Host_B】啊？一年？你说的这个小国多大？
【Host_A】大概 30 万人口那种，冰岛级别的。
【Host_B】哈哈那确实夸张。但这电主要是算力吧？不是制冷？
【Host_A】一半一半，真正震撼的是——训练完了一次，模型就固定了。
【Host_B】对啊，就是一次性消耗。这么看，其实每 token 摊下来不贵。
【Host_A】你这个账算得对，但遗漏了一件事：每半年就要重训一次。
【Host_B】等等，为什么要重训？
【Host_A】因为世界在变，昨天的知识今天就过期了。
```

特征：
- 每段 15-50 字，短段为主
- 真实数据（30 万人口 / 半年重训）
- 追问递进（"一年？"→"是电还是制冷？"→"为什么重训？"）
- 金句潜力（"昨天的知识今天就过期了"）

## 角色名自定义

`Host_A` / `Host_B` 只是**技术标记**（决定 TTS 用哪个声音 + 声道位置）。
如果想用化名，在 system prompt 中追加：

```
- 两人互相用化名：Host_A 叫"小明"，Host_B 叫"小红"
- 正文中绝对禁止出现 Host_A / Host_B 字样
- 正确：【Host_A】小红你听听...  【Host_B】小明你这个比喻太好了...
```

同时在 `podcast_tts.py` 的 `DISPLAY_NAMES` 配置真名→化名映射。

## 故障排查

| 症状 | 原因 | 修复 |
|------|------|------|
| TTS 合成出音色漂移 | 单段超 290 字被切 | 检查 70% 短段占比是否达标 |
| 听起来像念稿 | 少语气词 / 长段太多 | 强化"对话质感"那节约束 |
| 前 30 秒就想关 | 没有钩子 | 首段改反直觉结论 |
| 信息水 | 素材太弱 | 补"对立视角"+"反直觉数据" |
| 话题跳跃生硬 | 缺话引 | 子话题间用"这让我想起" |
