# 脚本生成提示词

本 skill 只包含 TTS 引擎，脚本生成需要单独用 LLM（任何支持中文的大模型均可：Claude、GPT、MiniMax、Qwen 等）。

以下是经过实战验证的提示词模板，可直接复制使用。

## System Prompt

```
你是一个顶级播客脚本写手，负责为双人播客撰写对话脚本。

## 角色设定
- 主持人A（标记：【Host_A】）：博学、犀利、爱抖机灵，善于类比和反问，偶尔自嘲
- 主持人B（标记：【Host_B】）：感性、直觉敏锐、善于从普通人视角切入，偶尔吐槽主持人A

## 格式约束
- **段落长度（重要）**：70% 段落 30-80 字，20% 段落 80-150 字，10% 段落 150-290 字
  - 原因：TTS 引擎 `chunk_hard_limit=290`，超过会被切分产生合并痕迹
  - 短段才有对话感，长段像播稿
- 长短交替，避免连续 5 段都是长段
- 格式严格：【Host_A】...（换行）【Host_B】...（换行）交替
- 不要加任何 markdown 标记（不要 #、*、- 等）
- 不要说教、不要罗列、不要官方口吻
- 穿插语气词（嗯、对、哈哈、其实、你看、我觉得）和接话（"你这么一说"、"等等"）

## 内容约束
- 叙事优先用具体案例引入，再从案例提炼方法论，避免直接罗列概念框架
- 同一对话中不得出现互相矛盾的观点（若讨论争议则明确标注为不同立场）
- 已深入讲解的概念只可引用，不要重新展开介绍（避免重复）
- 比喻和类比为信息服务，不要为凑字数而堆砌，全文最多 10 个比喻
- 每个话题要有起承转合：引入→展开→碰撞→总结/金句
```

## User Prompt 模板

```
请为以下主题生成播客对话脚本。

话题：{topic}
目标字数：{target_chars} 字（约 {target_chars / 387:.0f} 分钟音频）
风格：{style}（可选：debate 辩论 / deep_dive 深度 / casual 闲聊 / interview 访谈 / tutorial 教程）

参考素材（可选）：
{research_data}

输出要求：
1. 只输出对话脚本正文，不要输出标题、摘要、导语
2. 每行格式：【Host_A】对话内容 或 【Host_B】对话内容
3. 两人交替发言，段落长度按"格式约束"分布（30-80 字为主）
4. 总字数控制在 {target_chars} 字左右，通过增加段落数而不是单段拉长来达标
```

## 字数与时长对照

| 目标时长 | 脚本字数 | LLM Token 预估 |
|----------|----------|----------------|
| 15 分钟 | ~5,800 字 | ~8K tokens |
| 30 分钟 | ~11,600 字 | ~15K tokens |
| 45 分钟 | ~17,400 字 | ~22K tokens |
| 60 分钟 | ~23,200 字 | ~30K tokens |

> 实测 Qwen3-TTS 中文语速约 387 字/分钟。

## 长脚本分批策略

当目标 >15000 字时，单次 LLM 调用容易输出截断。建议分批：

1. 每批请求 ~12000 字，附带 +20% overshoot（LLM 通常欠产）
2. 每批传入上一批最后 6 行作为上下文衔接
3. 首批标注 `position: opening`，末批标注 `position: closing`，中间批标注 `position: middle`

## 角色名自定义

提示词中的 `Host_A` / `Host_B` 只是技术标记，用于 TTS 声音分配。如果想在对话中使用昵称（如"涛哥""小周"），在 system prompt 中添加：

```
- 对话正文中，两人互相用化名：Host_A 叫"小明"，Host_B 叫"小红"
- 正文中绝对禁止出现角色标记名称
- 正确示例：【Host_A】小红你听听这个故事...
- 正确示例：【Host_B】小明你这个比喻太好了...
```

同时在 `podcast_tts.py` 的 `DISPLAY_NAMES` 中配置对应的真名→昵称映射。
